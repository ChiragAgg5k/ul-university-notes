# Digital portfolio, phase 2

A React application that presents Chirag Aggarwal's education, projects, writing and media. It is the second phase of a coursework project for CS5709 Software Engineering Evolution at the University of Limerick. Phase 1 was a static site generated by a Node script; this phase rebuilds it as a single-page application with typed code, JSON-driven content, shared state, an outside API, a database and an automated deployment.

- Live site: https://chiragagg5k.github.io/ul-university-notes/
- Source: https://github.com/ChiragAgg5k/ul-university-notes/tree/main/2026-27/SEM1/CS5709%20-%20Software%20Engineering%20Evolution/Assignment%203/site
- Phase 1, kept for comparison: https://chirag-cs5709.appwrite.network

This file is also the Readme page of the site: the page imports this text, so the two can't disagree.

## 1. Overview and how to run

Requires Node 22.18 or newer.

```sh
npm install
npm run dev          # development server on http://localhost:5173
npm test             # unit tests (Node test runner)
npm run lint         # oxlint
npm run format       # Prettier
npm run build        # type check, then production build into dist/
npm run preview      # serve dist/ on http://localhost:4173
npm run walkthrough  # scenario walkthrough in a real browser, against the preview server
```

| Tool | Version | Why this one |
| --- | --- | --- |
| Vite | 8 | Development server and bundler; splits each lazy import into its own file |
| React | 19 | Component model the module teaches; `use`, `lazy` and document metadata are built in |
| TypeScript | 7, strict | The brief allows PropTypes or TypeScript; types are checked before every build |
| React Router | 7 | Client-side routes with one lazy chunk per page |
| GSAP | 3 | Entrance animation, switched off for visitors who prefer reduced motion |
| Appwrite | SDK 29 | Hosted database and realtime channel for article reactions |
| marked | 18 | Turns this file into the Readme page |
| oxlint, Prettier | | Static checks and one formatting standard |
| Node test runner | built in | Unit tests with no extra dependency |
| Playwright | 1.65 | Drives a real browser for the scenario walkthrough |

## 2. Architecture

### Pages

| Address | Page | Content source |
| --- | --- | --- |
| `/` | Home | `data/profile.json` |
| `/about` | About | `data/profile.json` |
| `/education` | Education | `data/education.json` |
| `/knowledge` | Professional knowledge, with search and skill filter | `data/projects.json` |
| `/pictures` | Pictures gallery, with search, tag filter and enlarged view | `data/photos.json` |
| `/videos` | Video gallery with captions | `data/videos.json` |
| `/blog` | Blog index, with search and topic filter | `data/posts.json` |
| `/blog/:slug` | One article, with reactions | `data/articles/*.html`, Appwrite database |
| `/repositories` | Latest public repositories | GitHub REST API |
| `/contact` | Contact details and live chat | `data/profile.json`, Tawk.to |
| `/readme` | This document | `README.md` |
| anything else | Page not found | |

### Folders

One concern per folder. A page never talks to an outside service directly; it goes through a hook, and the hook goes through `api/` or `chat/`.

```
site/
  README.md             this document, also shown at /readme
  public/assets/        images and the video, served as they are
  tests/                unit tests and the browser walkthrough
  src/
    main.tsx            browser entry point
    App.tsx             route table; every page is a lazy chunk
    pages/              one file per route
    components/         pieces shared by pages (Layout, Page, CollectionFilter, Reactions, ...)
    hooks/              React glue: useFilter, useChat, useReactions, useReveal
    state/              filter state: context, reducer and matching rules
    api/                calls to outside services (GitHub, Appwrite)
    chat/               Tawk.to loader: consent, loading states, failure
    data/               all content, as JSON and article HTML
    types/              shapes of outside data
    index.css           one stylesheet, with design tokens at the top
```

### Module view

Arrows read "imports". Dashed arrows are dynamic imports, which become separate downloads.

```
main.tsx ──> App.tsx ──> state/PortfolioProvider ──> state/PortfolioContext (reducer)
                │
                ├──> components/Layout ──> components/Chat ──> hooks/useChat ──> chat/loader ··> Tawk.to
                │
                └··> pages/*  (one chunk each)
                       │
                       ├──> components/Page, CollectionFilter, ProjectCard, VideoPlayer
                       ├──> hooks/useFilter ──> state/PortfolioContext
                       ├──> state/matches   (pure filtering rules)
                       ├──> data/*.json
                       ├──> pages/Repositories ──> api/github ··> GitHub REST API
                       ├──> pages/Article ··> data/articles/*.html
                       │         └──> components/Reactions ──> hooks/useReactions
                       │                   └··> api/reactions ──> appwrite SDK ··> Appwrite database
                       └──> pages/Readme ··> README.md, marked
```

### State

- **Filters** (`state/`): one search text and one selected tag for each of the three filterable collections, held in a reducer above the router. A visitor who filters the projects, opens an article and comes back finds the filter as they left it.
- **Chat** (`chat/loader.ts`): a small external store with five named states, read through `useSyncExternalStore`. Nothing is requested from Tawk.to until the visitor clicks.
- **Reactions** (`hooks/useReactions.ts`): counts are loaded once, then raised by realtime events.

### Article reactions

Under each article a reader can leave one of three reactions. They are rows in an Appwrite table (`article`, `kind`). The table's permissions let anyone create and read rows and let nobody update or delete them, so the browser can write to it safely without a server in between and without an account. The row identifier is built from a random visitor identifier, a hash of the article and the kind, so the database refuses a duplicate. A realtime subscription raises the counts on every open copy of the article the moment anyone reacts.

Known limits: a visitor who clears browser storage can react again, and a reaction can't be withdrawn.

### Loading

The first download holds the frame, the router and the filter state. Each page, each article's text, the Appwrite SDK and the Markdown renderer are separate files fetched when first needed. Gallery images use `loading="lazy"` and the video loads its metadata only.

## 3. Testing and known issues

| Check | Command | What it covers |
| --- | --- | --- |
| Unit tests | `npm test` | Filtering rules, the filter reducer, reaction identifiers, and that the content files agree with the routes and assets |
| Static analysis | `npm run lint` | oxlint with the React and TypeScript rule sets |
| Types | `npm run build` | Strict TypeScript, checked before bundling |
| Formatting | `npx prettier --check src tests` | One coding standard |
| Walkthrough | `npm run walkthrough` | Persona scenarios in a real browser at desktop and phone width, with screenshots |

Known issues:

- GitHub Pages has no rewrite rule for single-page applications. The build copies `index.html` to `404.html`, so a deep link such as `/knowledge` renders correctly but is answered with HTTP status 404.
- The Repositories page uses the GitHub API without a token, which allows 60 requests an hour per address. Beyond that the page shows its failure message and a link to GitHub.
- Live chat depends on Tawk.to. If the widget can't load within 20 seconds the button reports that and offers email.

## 4. Pipeline

`.github/workflows/cs5709-portfolio.yml` at the repository root runs on every push and pull request that touches this folder.

| Job | Step | Fails when |
| --- | --- | --- |
| `check` | `npm ci` | The lock file and `package.json` disagree |
| | `npm run lint` | oxlint reports an error |
| | `npx prettier --check src tests` | A file is not formatted |
| | `npm test` | A unit test fails |
| | `npm run build` | A type error or a bundling error |
| | upload the `dist/` artifact | (only on `main`) |
| `deploy` | `actions/deploy-pages` | (only on `main`, only after `check` passes) |

Pull requests and other branches run the checks without deploying. GitHub Pages serves the repository under `/ul-university-notes/`; the workflow reads that path from the Pages configuration and passes it to Vite as `BASE_PATH`, and the router takes the same value as its base name. Local builds use `/`.
